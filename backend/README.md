# CertiChain Backend

FastAPI + SQLAlchemy + PostgreSQL/SQLite + SHA-256 + Solidity/Web3 certificate registry.

## 1. Local setup

```bash
cd backend
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
copy .env.example .env   # Windows
# cp .env.example .env   # macOS/Linux
```

Set a real `JWT_SECRET_KEY`.

Run:

```bash
uvicorn app.main:app --reload
```

Open `http://127.0.0.1:8000/docs`.

## 2. Blockchain setup

Compile and deploy `contracts/CertificateRegistry.sol` using your chosen Ethereum-compatible testnet/development chain.

Replace `abi/CertificateRegistry.json` with the ABI generated by your Solidity compiler if it differs from the supplied ABI.

Set:

```env
BLOCKCHAIN_ENABLED=true
BLOCKCHAIN_RPC_URL=...
BLOCKCHAIN_CONTRACT_ADDRESS=...
ISSUER_PRIVATE_KEY=...
```

Never commit `.env` or a private key.

## 3. Important production note

The included `LocalStorage` adapter is intended for development. For production, replace it with private S3/GCS/Azure Blob storage and serve files only through controlled access.

Use PostgreSQL in production and run Alembic migrations instead of relying on `create_all()`.

## 4. API

- `POST /api/auth/login`
- `POST /api/auth/register` (disabled by default)
- `POST /api/certificates/issue`
- `GET /api/certificates/{id}/verify`
- `POST /api/certificates/verify/file`
- `GET /api/certificates/{id}`
- `POST /api/certificates/{id}/revoke`

## 5. Security model

- Passwords are Argon2-hashed.
- Issuance requires an authenticated issuer.
- Blockchain issuance fails closed if blockchain is unavailable.
- Exact file bytes are fingerprinted with SHA-256.
- Private blockchain credentials stay server-side.
- Certificate PDFs are not stored on-chain.
